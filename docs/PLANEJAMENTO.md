## Regra para commits importantes

O Git registra automaticamente a data real de cada commit. O prazo é controlado pela Issue:

1. Todo commit importante referencia a Issue: `(#número)`.
2. O commit é enviado durante a janela planejada.
3. Código não fica acumulado localmente para ser enviado apenas no último dia.
4. Código, teste, configuração, documentação e evidência continuam separados.
5. A data-alvo é o limite para PR revisável, não o momento de começar.
6. Correções de review geram novos commits antes do fechamento.
7. Nenhum commit é artificialmente criado ou pré-datado apenas para preencher cronograma.
8. Pull Requests não utilizam squash.

## Fluxo do quadro

| Status | Condição |
|---|---|
| Backlog | Tarefa conhecida e ainda não preparada |
| Ready | Dependências, critérios, testes, data e evidência definidos |
| In progress | Responsável e branch; apenas uma Issue principal por integrante |
| In review | PR aberto antes da data-alvo, pipeline e evidências disponíveis |
| Done | Revisão aprovada, merge sem squash e RTM atualizada |

## Definition of Done

- [ ] Cada alteração concluída possui commit coerente.
- [ ] Código, teste, configuração, documentação e evidência estão separados.
- [ ] Testes relevantes e `./mvnw -B verify` passam.
- [ ] JaCoCo, SonarCloud e segurança aplicáveis passam.
- [ ] Não existe bug nem vulnerabilidade crítica confirmada e aberta.
- [ ] RTM e evidências apontam para o mesmo commit/tag.
- [ ] Outro integrante revisou o Pull Request.
- [ ] Merge ocorreu sem squash.
- [ ] A Issue foi concluída até sua data-alvo.
